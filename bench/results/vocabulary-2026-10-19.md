# 词典：各模型带不带词典（2026-10-19）

这一轮评的是词典的效果：同一批真实录音，每个模型各跑两遍，一遍不带词典、一遍带作者自己的词典，数专有名词认对了几个、没说到的词有没有被硬塞进去。走的是产品里的同一条路，词典的收法和上限都按模型清单。

本文只放汇总数字。逐条的录音、参照和各模型的成品在本机的 `bench/_work/vocabulary/`，不进仓库。

## 条件

- **代码**：分支 feat/vocabulary，`c5a744f` 起（评测脚本 `scripts/dev/eval-vocabulary.mjs`，判法在 `bench/lib/vocabulary.mjs`）。
- **机器**：一台 Apple 芯片的 Mac。本机模型：transcribe-cpp 0.4.0（Metal），sherpa-onnx-node 1.13.8（CPU）。
- **词典**：作者在原版里的那份，27 个词（专有名词、术语、中文词都有，用逗号连起来 171 字）。除 sherpa-onnx 版 Qwen3-ASR（上限 120 字）外，各模型的收词上限都没碰到。
- **样本**：原版 Typeless 历史里的 127 条口述录音，6–89 秒（中位 28 秒），共 70 分钟。
  - 51 条含生僻词：Grok、multica、Runzo、AE-PM、Garmin、harness。这些词的录音能找到的全收了。
  - 36 条只含常见词：Claude Code、埋点、全量，各挑约 12 条。
  - 40 条一个词典里的词都不含，当反例。
  - 合计要认出 90 个词。
- **参照**：原版的成品。原版当时也开着同一份词典，所以参照里的写法就是作者要的写法。
- **判法**：
  - 认对：成品里出现这个词。不分大小写，空格不算差别；英文词前面不能紧挨字母，ngrok 不算 Grok。说"佳明"写佳明或 Garmin 都算对，这条是作者定的。
  - 写法全对：大小写也一字不差。
  - 硬塞：成品里出现了词典里的专有词，参照里却没有。cli、App、agent、load、onboarding 这类平常就会说的词不算。
- **原生识别**：用 App 的提示词，思考档位 MINIMAL。
- **润色**：输入是本机 Qwen3-ASR（Q8）不带词典转出的原文，带不带词典用同一份。只看润色这一跳。

## 读法

- 收词典的模型都有明显提升。读提示词的大模型（原生、润色）提升最多，认对的词多出 30 多个。
- 转写模型里，**百炼 qwen3-asr-flash** 和**智谱**涨得最多，都在 35 个上下。fun-asr 收上下文，但几乎不拿它纠正生僻词，只多认对 5 个。
- 本机的 Qwen3-ASR，transcribe-cpp 版能多认对 28 个。sherpa-onnx 版的热词上限是 120 字：它的 KV 缓存只有 512 个位置，词多了会挤掉录音。所以这份 171 字的词典它只收下前 15 个词（118 字），算分的 harness、埋点、全量都没收进去，只多认对 11 个。
- 带词典几乎不增加耗时。
- 硬塞多出来的主要在 DeepSeek 润色（+7）和 fun-asr（+5），逐条的成因见下一节。

## App 端到端

真的 Electron、真的录音编码和模型，只有麦克风换成录音文件（`scripts/dev/e2e.mjs`）。数据目录里放上同一份词典，拿一条 12 秒、说了 multica 的录音（52c3f333），三种识别方式各跑一遍：

| 方式 | 成品里那个词 |
| --- | --- |
| 数据隐私（本机 Qwen3-ASR Q8），不带词典 | Monte Carlo |
| 数据隐私，带词典 | Multica |
| 转写 + 润色（本机 Qwen3-ASR Q8 + DeepSeek Flash），带词典 | multica |
| 原生识别（Gemini 3.6 Flash），带词典 | multica |

四遍的录音、上传、整理、贴字、存历史、记账都走通了。第一次跑时，数据隐私和转写 + 润色两种方式都装不上本机模型：模型清单里百炼热词的规矩写成了函数，配置整项交给转写进程时复制不过去。单元测试用的是假的转写进程，评测是在同一个进程里装模型，都没碰到这一步。改成纯数据后（`e44b10e`），四遍都通过了。

## 已知的问题

- **参照本身的错**（这几条按参照判，所有模型同样吃亏，或同样被记成硬塞）：
  - 02f14ca1：参照里写了 Garmin、Whoop，各路转写和原生模型都没听到这两个词，录音里应该没说。
  - 4bde555c：参照写"埋点"，各路都听成"卖点"，语义上"卖点"更通。
  - 929ef798：参照写"Grok Body"，9 个模型都写成词典里的 Grok Bot，说的应该就是它；判分记成硬塞。
  - 0b523768：参照写"Codex 或者 CodeX"（原版自己写重了），4 个模型写成"Claude Code 或者 Codex"；判分记成硬塞。
- **multicard**：有 5 条参照写的是 multicard 或 MultiCard，判法按前缀认，把它们算成含 multica；成品写成"multi card"（中间有空格）却不算。影响的格子很少，带不带词典两边一样受影响。

## 硬塞的成因

带词典那一遍的硬塞逐条看过，分三类：

| 类 | 次数 | 是哪些 |
| --- | --- | --- |
| 参照错了，模型写的才对 | 13 | 929ef798 的 Grok Bot（9 个模型）、0b523768 的 Claude Code（4 个模型） |
| 说法不明 | 2 | 31cc7a8c：参照写"Blaze Code"，两个润色模型写成 Claude Code |
| 真硬塞 | 17 | 见下 |

真硬塞：

- **DeepSeek 润色 7 次**，都是把原文里另一个名字换成了词典词：人名"乐挺"换成 Runzo，"App Store""AE platform""AE Sparky Brainstorm"换成 AE-PM，"scale-ae"换成 Claude Code，"join"换成 Grok Bot，"登山档案"前面凭空加了 Garmin。它是润色模型里最敢改的，认对得多，硬塞也多。
- **fun-asr 把上下文原样吐进转写 4 次**（2 条录音）：成品里冒出"Grok Bot，closing moon，cli."，正是词典的前三个词。百炼的 fun-asr 收上下文的方式是录音前的一条消息，录音里有停顿时它会把这条消息当成说的话。
- **Qwen 润色 2 次**：把 Multica 换成了 Claude Code、chiikawa（词典里别的词）。
- **本机 Qwen3-ASR Q8 2 次**：Cloudflare 写成 Claude Code，Claude Code 写成 Grok Bot。
- **Gemini 1 次**：AE Sparky Brainstorm 写成 AE-PM。
- **智谱 1 次**：一串听不清的字母写成了 HRV。

fun-asr 的问题和别的不一样：它不是把相近的词认成词典词，而是把词典本身写进了成品。它带词典只多认对 5 个词（49 → 54），这个代价要不要付，值得单独定。
