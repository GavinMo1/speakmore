Typeless 仿刻的下一阶段是打磨成能开源的产品。用户 2026-10-13 在合并推送之后、压缩对话之前给的方向，原话：

> 咱们要把这个项目开源，起码要先达到开源的标准：能让用户一下子跑起来，并且有一个比较直观的面板。先不用考虑桌面端 App 的事，那个之后再做，不是现在做，能明白吗？总之就是要打磨得更简洁易用一点。咱们的目标就是用户一安装下来，填一个 Gemini 的 key 上去，立马就能用起来，整体向 Typeless 这个产品看齐吧

他同时发了三张原版主窗口的截图当参照，存在 `targets/typeless/_work/ui-reference/`（不进 git，历史那张里有他说过的话）。三张的共同结构是左侧导航（首页、历史记录、词典）加右侧内容区，左下角一排小图标（账号、反馈、设置、帮助）：

- 首页：大标题，一组"洞察"数字（口述字数、节省时间、平均口述速度、总口述时间、活跃天数和连续天数、按周排的热力图），右边一栏列出各功能的热键。
- 历史记录：按天分组的列表，每条是时间加文字，失败的那条带"重试"；上方有"保存历史多久"的设置和"全部 / 听写 / 问任何问题"的筛选。
- 词典：词条网格，分"自动添加"和"手动添加"，右上角"新词"和搜索。

**Why:** 第一轮把启动做成了"装进应用程序的应用 + 设置窗口"，他看过之后认为方向对，但要求换一个标准来衡量：不是他自己用着顺手，而是陌生人从仓库拿到就能跑起来。

**How to apply:**

- 评判每个决定时问"一个刚克隆仓库的人，要几步才能说出第一句话"。安装步骤、报错提示、README 都按这个人写。
- 面板照原版主窗口的结构来，范围仍受 [[typeless-clone-scope-dictation]] 约束：只做语音转写，截图里的"翻译""问任何问题""云同步""推荐朋友"不做。词典是不是这一阶段要做的，他没说，是我看截图想到的，动手前问一句。词典正好对应现在和原版差得最多的地方（专有名词听错）。
- "桌面端 App 先不做"这句我的理解是：不做面向下载分发的那一套（签名公证、安装包、自动更新）。上一轮已经做了的本机打包（`npm run install-app`）要不要保留、算不算他说的"桌面端 App"，我没有把握，压缩回来后先确认这一点再动手。他那句"现在客户端和服务端都是通过本地命令行来启动的"和上一轮的结果对不上，可能是指安装这一步仍然要敲命令。
- 开源之前有几样东西要他拿主意（这是我的观察，不是他提的）：仓库里的 `.memory/` 和 `AGENTS.md` 写着本机的凭据名、目录和个人工作习惯；`targets/typeless/docs/` 是对一个商业产品的逆向分析；仓库名和历史提交是否原样公开。动手整理前先列给他。
