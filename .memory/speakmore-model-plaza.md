2026-10-16 他定的。本地转写的模型广场不替用户做决定，能接的模型都接上，用评测结果给每个模型打标签、写简介（哪种芯片、哪个系统上跑得最好，中文、中英夹杂各什么水平），推荐可以给，选择留给用户。

他的原话："咱们不要去替任何人或者模型做主。咱们测出 benchmark、跑通 pipeline 后，给这些模型打上 tag，加上简介，说明它们在各个场景下的具体表现就行。"

**Why:** 项目有了反响，用户的机器各不相同（已有人 fork 去做 Windows），一个"官方首选"替不了所有人。
**How to apply:**
- 推荐写成"在某种机器上最合适"，不写成唯一答案。例：Apple 芯片上 Qwen3-ASR 0.6B 的 Q8（transcribe.cpp 加 Metal）最准，SenseVoice Q8 最快。
- 标签只来自实测数据，没测过的平台（Windows、Intel）写"未实测"，不按推测打标签。
- Windows 上的原生端到端测试暂时放下，先把能在本机做的做好。
- 评测流程见 bench/README.md，判官是 Claude，见 [[bench-judge-is-claude]]；两条链路的关系见 [[speakmore-two-pipelines]]。

**2026-10-16 又定的结构（扩充到云端模型时）：**
- 百炼走国内站。顶层按角色分：原生（一步）、转写（下分本机、云端）、润色；Key 按平台另放。
- 各家官方的 key 也要单独接，不能只靠百炼：他的原话"很多人是只用一家的，比如说 kimi/deepseek/glm 啥的，虽然百炼也有，但不是同一个 key，所以得单独列出来"，再加上海外用户用不了百炼国内站。同一个模型在几个平台都有时，做一张卡、标出经由哪些平台。
- 模型从设置里搬出来，放到主窗口侧栏，单独一页，"像逛商场一样"。
- 对接口差异的态度："反正就是策略模式，有不同的情况单独拎出来处理就好了……对用户来说不就是填写一把 key 就能直接做了吗……要有用户思维"。百炼里调用方式不统一的部分（转写要用 DashScope 自己的写法）由我们在适配器里处理掉，不让用户感知。

**2026-10-16 原型（还在改，等他看完再动）：** 在 scratchpad 的 `plaza/`，`index.src.html` + `plaza.css`，`plaza-build.mjs` 把图标拼进去生成 `index.html`，直接引用仓库里的 tokens/window/hub.css；本地用 Chrome 打开，不发 claude.ai（[[html-stays-local]]）。他看过后提的两条已改：
- 两种模式不能像流水账一样列两行，用户看不懂。改成"用法"一段：并排两张卡，各画一条录音 → 模型 → 成品的路，在用的那张描主题色边、线上走光，底部一行写这种用法意味着什么（录音出不出本机、发给谁）。
- 标签要有固定词表，不能想到哪写哪。全广场只留四种：默认、实测、未实测、已知问题（悬停看是什么）。本机模型的特点改成固定的规格列（中文、中英混说的满分 5 圆点，转 1 分钟要几秒，内存，下载），每列最好的标绿；Q8_0/int8 改叫 Metal 版/CPU 版。

**2026-10-16 第三版（照规范重做）：** 他嫌按钮、分类条、渠道切换"像极其普通的表单"，各行按钮参差，"能用"这类文案太低级，原话"我觉得是咱们缺少一套规范，你先做""不要我说一步你做一步"。于是先立规范、再整页重做：
- 规范页 `plaza/spec.html`（源 `spec.src.html`），控件层 `plaza/ds.css`，原型和规范页共用；合进 App 时 token 并 tokens.css、控件并 window.css（按钮沿用 `.button` 类名）。规范七节：文案词表、三档控件高度与四档圆角、按钮四种、检测状态一套、选择控件五种、列表定宽列、门禁。
- 用词改了：用法→识别方式，挑模型→模型库，经由→渠道，Key→密钥，检查→检测，实测/未实测→已评测/未评测，使用→启用。
- 列表：每表有表头；状态列、操作列各 6rem、控件撑满；没密钥的组在表头下一行提示加一个"配置密钥"，行内"启用"置灰。
- App 主窗口默认 1080×750、最小 988：原型按这两档量过（`#audit` 量各表状态、操作列边缘和截断），宽时识别方式两卡并排，窄时上下叠。
- 门禁三项（文案词表测试、尺寸 token 测试、边缘对齐）写进了规范，前两项要等合进 App 时再接。

**2026-10-16 第三版定稿：** 他说"这个原型页我很满意，很规范，彻底 OK 了"，下一步正式开发：照原型把模型从设置搬到侧栏、百炼的模型全部跑通（先只求每个模型用一条录音能出结果，不跑 benchmark，"以后再考虑跑得好不好"）；DeepSeek、Kimi、GLM、MiniMax 官方接口由并行的 agent 照官方文档接，暂无 key、先不验证。他要求压缩对话后再正式开工。
