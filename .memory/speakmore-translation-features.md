2026-10-22 发完 0.15.0 后他提的，说"回来再探讨"，还没开工、没有设计：

1. **说话翻译（同声传译 / 翻译）**：说 A 语言，出来的是 B 语言的文字。
2. **划词翻译**：鼠标选中任意文字后弹出对应的翻译。他自己说这个和现在的基座产品（热键听写、贴进输入框）形态冲突很大，要先想清楚产品形态怎么设计。

他的判断：内核估计是共用的。我当时的初步看法（没验证）：
- 说话翻译可以落在现有链路的整理那一步：原生链路让收音频的模型直接出目标语言；转写加润色链路在润色那一跳翻译。可能是一种模式或一个"目标语言"设置，复用录音、上传、贴字、历史和记账。
- 划词翻译不经过录音，是"文字进、文字出"，可以复用润色那一层的厂商和模型（`src/server/chat/`）；要新的是取选中文字（小帮手那边）、触发方式和弹出的界面。

定位口径见 [[typeless-clone-scope-dictation]]（语音输入，之后做同声传译和翻译；会议纪要不做）。谈的时候按 [[decisions-as-options]] 把要他定的做成选项。
